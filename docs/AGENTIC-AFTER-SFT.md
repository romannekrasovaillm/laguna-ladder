# Агентность после SFT: что измерено и чего эти числа не доказывают

Замер сделан на завершённом SFT-состоянии (одна модель, один чекпойнт — замороженная копия, ADR-058).
Публикуются только агрегаты; данные задач, отчёты и цитаты остаются внутри периметра (ADR-048).

## Что и как измерялось

| Параметр замера | Значение |
|---|---|
| Состояние | SFT-финал (компактная доменная модель класса ≤1B) |
| Форсирование вызова | **нет** — вызов инструмента модель должна сделать сама |
| Подсказка (открывающий тег) | **нет** |
| Режим декодирования | штатный: сэмплирование T=1, top_k=20, **запрет повторов 4-грамм** |
| Попыток на задачу | 1 (pass@k не заявляется) |
| Ходов на траекторию | ≤ 5 |
| Пулы | A — 150 задач; B — 200 задач |

## Две метрики и их разный смысл

- **`tool_call` (навык действия)** — доля траекторий, в которых модель **сама** вызвала инструмент.
  Без форсирования и без подсказки это измерение модели, а не харнесса.
- **`pass-rate` (навык решения)** — доля задач, принятых бинарным верификатором.
  Кредит бинарный: не вызвала инструмент → ответа нет → ноль. Поэтому провал по действию
  автоматически тянет вниз решение, но обратное неверно: вызов есть — решения может не быть.

## Числа

| Пул | n | самостоятельный вызов | pass-rate |
|---|---|---|---|
| A | 150 | **0.46** | **0.04** |
| B | 200 | **0.45** | **0.05** |

Единственный тип задач, измеренный на обоих пулах (сопоставимая строка): вызовы 0.42 против 0.38,
pass-rate 0.12 против 0.08. Сводные доли отвечают на вопрос «где пул целиком»; построчно
сопоставим только общий тип.

## Что это значит

1. **Действие: примерно в половине траекторий.** Модель вызывает инструмент примерно так же часто,
   как раньше, — то есть навык «позвать инструмент» SFT не сломал.
2. **Решение: 4–5 %.** Это низко, и роста по сравнению с базой отсюда не видно.
3. **Доминирующий класс отказа — «нет вызова инструмента».** Больше половины траекторий вообще
   не доходят до действия; именно они, а не ошибки в решении, дают основную часть нулей.
4. **Прямое сравнение с прошлыми числами невозможно.** Прежние агентные числа сняты в другом
   режиме декодирования (без запрета повторов) и частично с форсированием вызова — то есть
   измеряли харнесс, а не модель. База обязана быть переснята тем же прибором, теми же флагами
   и в том же режиме; это в работе.

## Что из этого следует для RL-стадии

- Пул **пригоден как «непустой сигнал»**: 5 % решаемости против 2,9 % у базовой модели — то есть
  фигура «пул мёртв» относится к базовой модели, а не к пулу.
- Но **полоса трудности пуста**: задач с решаемостью 25–80 % нет ни одной. Обучение с подкреплением
  живёт на задачах, где сигнал есть и он не вырожден; без полосы группа сравнения даёт нулевой
  advantage.
- И **различие двух пулов не отделено от шума** (интервал разности накрывает ноль): на одной попытке
  на задачу выбор между пулами не обоснован.

Итог одной строкой: **SFT научил звать инструмент, но не научил решать; RL-ось на текстовом пуле
этим замером не обеспечена** — что и делает развилку «текстовый RL / заземлённый RL / закрыть точку»
решением по существу, а не по календарю.

## Границы

- Один сид, одна попытка на задачу: направление оси (RL против SFT) этим замером **не** устанавливается.
- Числа — агрегаты стадии; отчёты, наборы задач, цитаты и адреса артефактов не публикуются (ADR-048).
- Вердикт по критерию стадии (доля вызовов не падает / pass-rate растёт) выносится только после
  переснятия базы в том же режиме; до этого любые «рост/падение» — предварительные.
